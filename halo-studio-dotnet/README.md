## 2.6.4 后台启动、温度与网速

开机托盘启动不再先显示白窗。独立温度首次启用后，经一次 UAC 建立固定采集器的受保护按需任务；以后开机或手动启动均复用授权，主程序继续普通权限运行。网速改为活动物理网卡计数，排除 VPN／TUN 重复统计；完整单位明确为 KiB/s、MiB/s，原始字节计数无需除以 8。[实现、授权与清理说明](docs/STARTUP_NETWORK.md)。无需刷写 MCU。

## 2.6.3 歌词兼容性修复

修复播放器只报告主歌手时，多歌手歌曲的有效播放进度被丢弃、歌词退回监控画面的问题。保留精确歌曲 ID 和原有时间轴，并校验歌名、主歌手与已知时长，避免串用其他歌曲。原有歌词来源、提前量及固件均未改变。

## 2.6.2 首次启动与权限提示

独立 CPU 温度采集首次默认关闭，主程序不因这项功能自动请求管理员授权。用户主动打开开关或点击「授权并重试」后，才保存启用选择；下次启动恢复采集，驱动仍需要权限时可能再次出现 UAC。关闭开关会同时取消下次自动提权；取消系统授权后本次运行不反复弹窗。说明直接放在开启开关旁。

旧设置只有明确保存了温度授权标记才保留开启，旧版默认的 `enabled=true` 不当作主动选择。本次不修改 MCU、颜色或歌词逻辑。README 重排，新增 Win11 风格界面与主题效果图、功能摘要及限制说明。

## 2.6.0 逐字时间与普通短句分页

支持网易云 YRC：按照主题实际字形宽度分页，下一页使用首字／首词时间戳；没有有效逐字数据时只生成「开头...」「...结尾」两条普通歌词。为后半句预留传输与动画预算，稳定停到下一句；所有页面统一使用已选择的 MCU 过场，不持续传输滚动画面。默认提前 **0.8 秒**，手动偏移默认 0；暂停、拖动进度和主题变化都按真实时间重选页面。

本次同时整理歌曲版本缓存隔离、最小化后台同步、手动偏移和数值框失焦提交。逐字数据不是每首歌都有，极短页面也受 USB 吞吐限制。完整来源、公式和回退规则见 [歌词实现](docs/LYRICS.md)。**MCU 镜像未变，不需要为本次更新刷机。**

测试环境：Windows 11 专业版 x64，26H2 / **26300.9457**；网易云 **3.1.41.205564**；构建 SDK **.NET 10.0.401**。应用包自带 .NET 10，无需 Python、SDK 或 TrafficMonitor；在线取词需网络，温度驱动可能需 UAC，GPU 指标需 NVML。CPU 独立温度通道面向 AMD 17h/19h/1Ah，其余传感器取决于驱动支持。源码目标 API 10.0.19041 不表示所有旧版 Windows 已验证。固件工程才需要 Python 3.12 和固定工具依赖，详见 [固件命令流程](docs/FIRMWARE_USAGE.md)。
## 使用

从 [v2.7.0 Release](https://github.com/woozyc/pixelbardiy/releases/tag/v2.7.0) 下载 Windows x64 ZIP 并完整解压，运行 `HaloStudioNet/HaloStudioNet.exe`。源码构建后的入口为 `dist/HaloStudioNet/HaloStudioNet.exe`。安装包随附 .NET 运行时，不需要另外安装 .NET。

测试设备是 **花再 Halo PixelBar 2025 款常规版，USB 一线通**，2026-04-22 购入；不是强化版或 2026 款独立电源适配器型号。官方 2025 年说明书列出的参考型号为 EDF286015，本机铭牌编号未单独核对。

1. 从旧 HaloStudio 托盘菜单正常退出，等待音响恢复原厂时钟。
2. 打开新程序。本机测试包会复制既有 MCU 验证记录；分发包不包含设备身份信息，需要从设备页导入自己的 `mcu-installation.json`。
3. 在「主题与屏幕」挑选主题、颜色与默认内容，在「硬件监控」选择布局，在「音乐与灯光」查看当前句和灯光状态。
4. 关闭窗口会隐藏到托盘；点击「退出并恢复原厂显示」才会释放显示权。「设置 → HaloStudio → 切换到旧版本」会先完成释放，再启动原版。

「开机后台启动」使用当前用户的 Windows Run 项，不提权、不创建常驻服务。它与旧版共用 `HaloStudio` 启动项；勾选新版将该启动项指向新版。只运行一个版本。

独立 CPU 温度首次默认关闭。在「硬件监控」主动开启后，首次经 UAC 设置固定采集器的按需任务；以后重启和手动启动均复用授权，不再反复请求 UAC。采集器及固定材料保存在 Program Files 的受保护目录，主程序无需管理员权限；已有驱动优先复用。关闭开关停止调用，授权失效或辅助文件变更时才需重新设置。

## 2.5.4 后台歌词与 0.8 秒补偿

默认提前量改为 0.8 秒，手动时间轴偏移仍独立叠加。已保存的个人补偿值不会因升级被强制覆盖；本机按用户要求调整为 0.8 秒。

本机网易云 3.1.41 已验证独立播放进度读取：关闭桌面歌词、不打开歌曲歌词页、最小化窗口时仍可使用真实进度匹配当前歌曲 ID 的完整 LRC。无需 Python 或额外常驻服务。C# 仅以只读权限读取两个 8 字节时间字段，随已有媒体采样执行；不扫描进程内存、不写进程、不注入插件。只对 PE 时间戳 1791636812 / 映像大小 41054208 启用，未知版本继续使用既有兼容通道；未来网易云升级后可能需要重新适配。

本版网易云的 SMTC 在本机只提供歌曲与播放状态，时间轴为零；不能把它当作有效进度。已有有效系统时间轴仍受支持；原生进度通过有限值、时长和范围检查后才使用。默认时间轴来自播放器，暂停、跳转不会靠猜测时间继续播放。歌词内容来自当前版本缓存/网络或手动 LRC，离线且无缓存时无法生成未知歌词。

字段线索参考 [CloudMusic Local API 的公开版本记录](https://github.com/hanbinhsh/NetEase_Cloud_Music_Local_API#2026-10-新客户端适配)，在本机逐项核对后以 C# 独立实现；没有引入其 Python 服务。
## 2.5.3 歌词版本与首尾显示

歌词默认提前 0.8 秒请求刷新，抵消传输延迟；「刷新延迟补偿」和「时间轴偏移」独立保存，两者相加，手动正值再提前、负值延后。完整 LRC 优先于播放器的当前句，因此手动偏移也能作用于网易云本地通道。没有 Windows 播放进度时，以实际观察到的换句边界对齐 LRC；启动、暂停后恢复或重复歌词的候选位置不一致时，先显示当前句，等待可用边界，不把未知进度当成 0。没有完整 LRC 就不能提前预测下一句，界面会注明回退状态。短空白时间标签保留上一句，避免频繁切回默认画面。

网易云本地通道每 3 秒至多读取一次最近播放条目的歌曲元数据；使用 Windows 自带 SQLite，以只读方式核对歌名、歌手和歌曲 ID，再获取当前版本的歌词。缓存按歌曲 ID 隔离，不复用仅凭标题搜索到的其他版本；未确认版本的搜索歌词不覆盖原生分句，本地手动导入的 LRC 仍优先。这样避免“其他版本的合并句 → 播放器原生后半句”的重复。无需额外进程或 Python。

2.6.0 已将长句更新为普通时间轴分页，取代本节历史版本的 ACK 后首尾切换；具体行为见上方新版本说明。

数值输入支持 Enter、点击页面空白处或切出窗口立即提交并结束编辑；无效输入恢复上次有效值，超范围值限制在允许范围。完整有效的风扇键和额定 RPM 也会自动保存，原保存按钮保留。

开发验证：`--self-test` 覆盖时间轴、原生换句对齐、六主题首尾显示、版本缓存隔离与 USB 生命周期；`--preview --ui-page 2 --input-audit <报告路径> --quit-after 6` 在可见桌面窗口验证输入焦点；`--lyrics-probe --seconds 30 --output <报告路径>` 只读观察播放器，不连接 HID。报告包含本机歌词信息，不应提交到公共仓库。

## 2.5 校准色与连续过场

2.5.1 补齐全部主题原色的快捷入口，改用柔和红、绿、蓝，按近似观感的色相排序；修复高 DPI 下重新加载色表时色块变小、名称被裁切的问题。柔红是待实屏核对的新候选，其他主题校准值保留。

雷达终端采用实屏 G1 浅绿（设备 `#60FF30`），桃兔甜点采用 P2 淡粉（`#FF6048`）。两个颜色同时加入外部调色板；土黄仍为 `#FF6000`，本机白色仍为 `#FFFF90`。预览是近似观感，其他设备仍需校准。

配合新版换色固件，RGB 附在压缩帧头中，整帧 CRC 验证通过后才生效。换主题、演示换幕和同画面换色都保持独占，不再释放显示权、插入原厂时钟或等待原厂颜色命令。新增 32 步 MCU 本地「中心展开」「像素溶解」，主题入口过场由外部 JSON 的 `transition` 指定；同主题内容切换可在 UI 选择四种形式。关闭切换动画仍可直接更新。既有上推、揭幕、字符雨保留；正常退出或心跳超时才恢复原厂时钟和进入直绘前的配置颜色。

新能力只对已验证的新固件 SHA 开启，旧固件保留原有行为。每帧多传 3 字节，不增加包数；连续动画由 MCU 执行，不增加 PC 逐帧发送、亮度、电流或 PWM 时序。新固件和验证方法见 [换色与过场固件](firmware-color/README.md)。

## 2.4 自适应布局与双指标轮换

设置卡片根据内容区宽度排列为 1–3 列，2.4.1 用瀑布流将下一张卡片紧接在较短列下方，减少不同卡片高度造成的大块空白；窄卡片中的输入框自动移到说明下方。屏幕预览保持 8:1 并放大至接近可用宽度，随窗口一同缩放。侧栏加宽到 276 逻辑像素，按钮宽度扣除实际边距；旧版本入口收至设置页。侧栏底部状态区按内容自然高度贴底，文字和托盘按钮下移。实时硬件状态表移到监控页底部并保持通栏。自绘控件在尺寸变化时完整重绘，清除拖宽窗口时留下的旧圆角边缘。官方源码参考与布局说明见 [UI 布局](docs/UI_LAYOUT.md)。

双指标模式只使用已勾选的指标，优先组合 CPU 使用率/温度、内存用量/使用率、上传/下载、同一 GPU 的使用率/温度等。2.4.1 会继续给剩余指标配对：使用固定类别顺序 **CPU → 内存 → 显卡 → 磁盘 → 网络 → 风扇 → 其他**，每次选择类别距离最近的两个。距离相同优先取靠前的类别，同类别按传感器键稳定排序；显卡风扇归入显卡位置。偶数项全部配对，奇数项只在最后保留一个单项，数值变化不会改变配对。例如只选 CPU、磁盘读取和网络上传时，后两项距离更近，先配成一对，CPU 最后单独显示。

默认每次切换整对；在「硬件监控 → 显示编排 → 双指标横向轮换」可选择「每次一个」，此时按上述配对后的队列逐个接续。该选项用于横向切换，向上切换始终整组刷新。设置保存在 `pair_advance`，旧配置默认 `pair`。

## 界面与配色

界面参考 [Clash Verge Rev](https://github.com/clash-verge-rev/clash-verge-rev) 的侧栏、统一页头、设置行与圆角卡片结构，在 C# / WinForms 内实现浅色 UI。2.3 放大字体与控件、加宽侧栏，修复白色卡片四角和高 DPI 缩放；主题预览随窗口宽度排成 1–3 列，始终保持屏幕比例。硬件表、指标勾选、下拉菜单与风扇输入框采用同一套视觉样式。EXE、窗口、托盘统一使用 Halo 像素图标。

2.4.3 统一所有下拉框的浅色圆角、左对齐文字、箭头、悬停和当前选项勾选状态；展开列表使用同一字体、边框和强调色，支持方向键、Enter、Esc、F4 / Alt+下。显示指标卡片最高 480 个逻辑像素，按系统 DPI 缩放；标题和应用按钮固定，指标区内部滚动，采样更新不会重置滚动位置或未提交的勾选。

配色拆成设备输入与近似观感预览，运行时加载 `palettes/pixelbar.json`。快捷色按色相排列为柔红、土黄、浅绿、离子蓝、猫咪蓝、淡粉，最后为白色，覆盖全部六套主题原色；纯绿、纯蓝改用已核对的柔和主题色，新增柔红注明待实屏核对。主题缩略图、实时预览及演示预览使用同一张表。土黄、浅绿、淡粉和白色校准保持不变，已有自定义选择保留。文字反馈不足以精确测定 sRGB，色卡会注明近似观感；「设备 RGB…」允许手动选色，未校准值明确标注。编辑外部色表后点击「重新加载色表」即可生效。

「白色偏蓝校正」只在发送屏幕纯白时降低蓝色分量，校正值随本机设置保存，原始值为 255；本机已确认 144，即发送 `#FFFF90`，预览仍为目标白。每套主题独立保存颜色，对时钟、监控、歌词及演示中的该主题一致生效；音乐律动继续使用原有设备输入作为主色。覆盖值保存在本机 `settings.json` 的 `theme_colors`，已有自定义值保留。没有把基于白点猜测的全色域转换投入日常使用。

旧固件换色仍需释放显示权并等待约 3 秒；2.5 的换色固件已经改为帧内 RGB 提交。此屏幕是整屏共色的点阵，电脑预览不能保证浅色在面板上的观感；协议、实机观察与测试边界见 [颜色说明](docs/COLORS.md)。

## 功能与边界

- 256×32 全屏点阵：六套外部主题、时钟、八指标紧凑两行、双卡片、仪表、负载条、历史曲线。
- HPL2 RAM 直绘：按帧选择 raw/RLE/XOR-RLE；基于最后已确认帧做差分，定期独立关键帧。
- MCU 本地向上推入、横向揭幕。全屏动画固件支持完整 256×32 画面，所有边缘、图形、文字一起移动；日常显示只写 RAM，不上传图片资源或擦写 Flash。
- 网易云：Windows 媒体会话；对本机已验证的 3.1.39 / 3.1.41 模块，按精确 PE 指纹只读当前歌词。未知模块不套用地址、不扫描整个进程、不注入代码、不读取账户凭据。
- 本地 LRC 导入、缓存、网易云/LRCLIB 在线匹配；播放器没有时间轴时不会将 0 当作播放进度。
- 音乐律动读取网易云输出会话的真实瞬时峰值，使用 4 秒动态范围适配和攻放包络；不使用音量滑块模拟强弱，不录音。
- Windows CPU、物理内存、网络、磁盘、报告频率；NVIDIA NVML 温度/负载/功耗/风扇。硬件不提供的值显示 `--`。
- 独立 CPU 温度继续使用已有的 44 KB C 辅助进程：优先复用 WinRing0/PawnIO，缺失时才加载已校验的签名 PawnIO；不依赖 TrafficMonitor。支持范围与旧版相同：AMD Family 17h / 19h / 1Ah。
- 风扇驱动比例与 RPM / 用户提供的额定最大 RPM 分开显示，不用观测到的峰值冒充额定值。主板风扇可复用已运行的 LHM/OHM WMI 服务。
- 进程独占锁与 Python 版共用。正常退出先完成在途响应，再 RELEASE，再确认原厂时钟持续稳定；异常退出由 MCU 的 2 秒租约回收。

USB 桥接 ACK 延迟仍存在。语言重写可以减少解释器、Qt 和后台对象开销，不能改变 USB 固件响应时间。后台资源测试和兼容性检查记录见 [验证文档](docs/VALIDATION.md)。

## 外部主题

`themes/*.json` 在运行时加载，修改后自动重载，或点击「重新加载主题」。可以直接复制现有主题、改 `id` 和名称后添加，无需重新编译。主题定义布局、字体、图案、颜色和动画表达式，程序没有六套主题的分支逻辑。

绘图格式及完整示例见 [主题指南](docs/THEMES.md)。所有主题都提供 `clock`、`lyric`、`single`、`pair`、`dense` 五个场景。预览与硬件使用同一份像素数据。JSON 只支持受限算术表达式，不执行脚本、访问文件或控制 USB。

## 一键演示

点击右上角「一键演示」或运行 `HaloStudioNet.exe --demo`。约 59 秒的「星际来信」以绿色字符雨开场：32 列字符错速下落、带点阵拖尾，随后逐渐显露 HALO STUDIO。接着展示六套主题各一幕和四句原创演示歌词。结束后回到真实歌词或默认画面，应用继续运行。

`demos/showcase.json` 控制段落、时长、主题、颜色与演示文字，在每次启动演示时读取。演示使用模拟监控数据，不修改用户设置，也不操作播放器。字符雨固件在 MCU 内生成 160 步动画，默认 32 ms 一步，名义时长 5.12 秒；USB 只发送目标画面并维持心跳。实际节奏还受 MCU 主循环影响。桌面预览显示目标帧，不能作为面板实际刷新率测量。旧固件会使用其支持的标题过渡。

## 构建与验证

使用官方 .NET 10 SDK，在 PowerShell 中执行：

```powershell
.\scripts\build.ps1 -Dotnet dotnet
.\scripts\verify.ps1
```

自包含发布：

```powershell
dotnet publish src/HaloStudio/HaloStudio.csproj -c Release -r win-x64 --self-contained true -o dist/HaloStudioNet
```

普通托盘启动：`HaloStudioNet.exe --background`。
离线运行：`--preview`；只读枚举：`--probe --output probe.json`。
离线协议与主题验证：`--self-test --fixtures tests/codec-vectors.json --output validation/self-test.json`。
短时实测：`--quit-after 60`，到时走完整释放流程；日常启动不使用这个参数。

主题与温度组件作为外部文件保留，因此采用 EXE 加资源目录的便携包。EXE 是 C# 编译的应用入口，自包含 .NET 运行时随包分发，不是 PyInstaller 包装，也不宣称 Native AOT。

## 固件

2.1 增加全屏动画与字符雨固件，兼容旧 HPL2 协议。客户端按本机已验证固件的 SHA256 启用对应能力：旧 codec 固件只对安全的中央歌词区使用本地动画，其他画面采用 PC 中间帧；全屏固件可对整个面板执行 32 步上推或揭幕；字符雨固件再增加本地生成的代码雨。客户端不会自动刷机。

固件及恢复边界见 [字符雨固件说明](firmware-matrix/README.md)和[全屏固件说明](firmware-fullscreen/README.md)。分发包附 BIN、源码及验证报告；更新工具需要完整工程和本机备份记录，不能脱离这些条件通用刷写。保留的旧固件文件可用于应用仍响应时回退；这不是设备完整 Flash 读回备份，显示 MCU 完全失效后的独立 USB 恢复尚未验证。升级只传显示 MCU，不改 USB/音频主控及引导区。
