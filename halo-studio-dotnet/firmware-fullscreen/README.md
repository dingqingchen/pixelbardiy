# HPL2 全屏动画扩展

本目录是已验证 codec 固件的小幅扩展。`codec_fullscreen_thumb.s` 新增动画 ID 3（256×32 上推）和 4（256×32 揭幕）；0/1/2 保持旧语义。动画仍在主循环执行，不在中断内绘图，不新增 RAM 缓冲，不擦写图片资源。

| 剩余回收代码空间 | 1,620 字节 |

固件先完整接收和校验新帧，保留旧帧，再在 MCU 本地生成中间帧。PC 端收到完整提交 ACK 后，等待动画完成再发下一个 BEGIN，避免下一次传输提前结束动画。无有效心跳约 2 秒后退出独占，恢复原厂显示。

## 验证与工具

`validate_fullscreen.py` 是纯离线工具，依赖`legacy-python/firmware-lab` 或相邻 `halo-controller/firmware-lab` 中的审计基线和固定 Unicorn 2.1.3 / Keystone 环境。它重建并核对基准 SHA，再验证真实 ARM 指令。所有检查通过后才导出新 BIN。

- 原有 19 组独占/生命周期和 8 组 codec 回归。
- 新增 11 组检查：两种全屏效果全部 8,192 像素、33 个状态（含起终点）、8/16/64 ms 间隔、计时回绕、动画中断、退出、心跳超时与非法 ID。
- 30 个原厂主题场景、16 个字形用例保持一致。
- 从当前 codec 更新到新固件，以及从新固件回到旧 codec，均以真实 OTA 指令仿真逐字节验证：各 1,041 包，标记只在完整接收后生成。
- 绘图/动画仿真没有触发 Flash 写入。OTA 验证中的 Flash 调用被模拟，不连接硬件。

`stage_fullscreen.py` 默认只核验备份和 USB 版本。写入需要明确 `--flash-authorized`；`--rollback` 选择已备份的旧 codec 文件。工具绑定精确 SHA、本机设备身份、成功验证报告、备份文件清单、独占锁和一次性尝试标记，不进行自动重试，不发送主控固件或强制重启。它依赖本项目本机准备记录，不能脱离完整工程当通用刷机工具使用。

`smoke_fullscreen.py --after-observed-reboot` 仅在精确传输完成且已人工确认重启后执行 RAM 测试；不会伪造“画面已验证”的记录。`--timeout-release` 测试停止心跳后自动恢复。

## 备份与恢复边界

本机备份在 `validation/pre-fullscreen-20261013-191923/`，包括原 codec 文件、官方恢复资料、原客户端及设备记录，346 个文件逐项核对 SHA256。私有记录不随应用包发布。

这份备份是已知固件文件和本机文件备份，**不是设备完整 Flash 读回**。应用仍响应时的回退传输已仿真验证；显示 MCU 完全失效后的独立 USB 恢复尚未证实。包中没有引导区或 USB/音频主控代码，缺失引导区意味着不能仿真证明最终安装和启动。物理画面、流畅度和恢复必须单独实测。

本轮实际升级已完整传输；用户已确认正常重启、全屏动画平滑且所有像素一起移动、正常退出和停止心跳后均恢复稳定时钟。完整本机日志保留在 `validation/fullscreen-live/`。
