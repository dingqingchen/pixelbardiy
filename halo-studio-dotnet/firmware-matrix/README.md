# HPL2 本地字符雨

为 256×32 面板增加动画 ID 5。32 列 5×7 字符以两种速度错位下落，三段拖尾用空间点阵疏密表现；最后从左至右显露提交的目标画面。单色面板不支持每个像素独立调亮度，绿色由原厂全屏颜色设置提供。

PC 只提交一次目标帧并维持心跳。160 步动画在 MCU 主循环执行，默认间隔 32 ms，名义时长 5.12 秒；不是通过 USB 逐帧上传图片，也不在中断里绘图。实际显示节奏受主循环负载影响。日常演示不擦写 Flash。

ID 0/1/2/3/4 的语义保持兼容。首次提交即可触发字符雨；动画结束时发布完整目标帧，使后续 XOR 差分基准一致。新画面可中断动画；错误所有者不能修改显示。正常 RELEASE 或约 2 秒无心跳都会回收独占并恢复原厂显示。

## 离线与实机验证

`validate_matrix.py` 依赖相邻 `firmware-fullscreen`、完整工程的 `legacy-python/firmware-lab`（本机分目录布局也支持`legacy-python/firmware-lab` 或相邻 `halo-controller/firmware-lab`） 和固定的 Unicorn 2.1.3 / Keystone 环境。它执行真实 ARM 指令并与独立像素模型对照，全部通过后才导出 BIN。

- 19 组生命周期、8 组 codec、11 组全屏动画回归。
- 7 组字符雨检查：全部 160 步、重复 tick、结束后的 XOR、退出、超时、中断及错误所有者。
- 保持 30 个原厂主题场景、16 个字形用例一致；绘图仿真没有触发 Flash 写入。
- 从前一版全屏固件升级到字符雨，以及反向回退，均通过真实 OTA 指令逐字节仿真，1,041 包。
- 2026-10-13 实际传输 1,041 包后，用户确认正常重启；三遍字符雨、标题、正常退出均正常；停止心跳后自行恢复时钟且稳定。

`validation.json` 是离线报告，因此其中 `device_accessed` / `firmware_written` 为 false。实机证据另保存在本机 `validation/matrix-live/`，含设备身份，不随便携包发布。

## 更新工具与恢复范围

`stage_matrix.py` 默认只核验备份与 USB 版本；写入需明确 `--flash-authorized`，回退选 `--rollback`。它复用已经检查过的 MCU 专用传输状态机，绑定精确 SHA、设备身份、备份清单和一次性尝试标记；不自动重试、不强制重启、不传 USB/音频主控代码。工具要求完整工程、本机已准备备份及设备记录，分发的脚本不是通用刷机器。

`smoke_matrix.py --after-observed-reboot` 是有界 RAM 显示测试；加 `--timeout-release` 会停止心跳而不发退出指令。它核对已完成的传输和设备身份，不伪造物理画面确认。

刷写前已逐项校验 352 个备份文件，包括前一版 BIN、应用、设备记录和官方恢复资料。备份目录是 `validation/pre-matrix-20261013-194629/`，不随包公开。这是已知文件备份，**不是设备完整 Flash 读回**。应用仍响应时的回退传输已仿真；显示 MCU 完全失效后的独立 USB 恢复尚未验证。包中不含引导区，无法仅靠该包仿真证明引导安装全过程。
