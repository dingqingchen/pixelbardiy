# 地平线 6 驾驶遥测

HaloStudio 2.7.0 新增 15 款复古汽车仪表。车速、挡位、转速和刻度直接跟随游戏变化；也可以不启动游戏，播放当前仪表的零百加速演示。

## 开始使用

1. 使用已支持 HaloStudio RAM 直绘的音响固件，USB 音源指示灯应为红色。**本功能不需要再刷一次 MCU**。
2. 打开 HaloStudio 左栏的「驾驶遥测」，选一款仪表，开启「接收游戏遥测」。首次默认关闭。
3. 在地平线 6 的「设置 → HUD 和游戏玩法」中开启 **Data Out**。IP 填 `127.0.0.1`，端口填 `20777`。
4. 回到游戏并开始驾驶。收到有效数据后，音响才会切换成仪表；同时播放网易云音乐时，屏幕优先显示仪表。
5. 暂停、离开驾驶或数据中断约 1.5 秒后，软件会继续显示原来的歌词、时钟或系统监控。关闭接收开关也会恢复。若日常屏幕显示本来关闭，则恢复原厂画面。

端口可以在软件中修改，游戏里需填同一个端口。请避开 `5200–5300`；这段端口由游戏使用。显示「端口占用」时，换一个未占用的端口即可。目前接收的是**本机游戏**，没有监听局域网地址，也不需要新增管理员授权。

## 零百加速演示

选择仪表后打开「遥测演示」，立即覆盖当前画面。演示持续约 16 秒：起步准备、模拟换挡、车速从 0 加速到 100 km/h，然后保持一下，自动回到之前的画面。随时关闭开关可以提前结束。演示中可切换仪表主题。

屏幕不额外叠加 DEMO / LIVE 字样，演示状态在应用里显示。这是一段用于展示效果的模拟过程，**不代表所选车型的实测零百成绩**。演示开关不会保存为下次启动自动播放；游戏遥测接收开关和所选主题会保存。

这些是为 256×32 单色点阵重新排布的主题，不是原车仪表的等比例复制。主车速使用较大像素数字，紧凑标签使用 3×5 字形；线条与读数相交的位置会为文字留出空间。

`RPM` 是发动机转速，`G/GEAR` 是挡位，`THR` 是油门，`BRK` 是刹车，`BST/BOOST/PSI` 是增压。全部 15 套主题的转速图使用每包 `EngineMaxRpm` 作为量程，按当前转速 / 最大转速缩放，换车或发动机上限变化后自动跟随；带数字刻度的主题也会更新刻度。超过上限时显示满格，最大转速为零的无效数据不会接管显示。未标数值的条形表表示相对量。BX 轮边块对应轮胎打滑，Renault 发动机图标对应发动机转动，制动图标对应手刹输入。车辆轮廓与部分线条只是装饰，不表示损伤诊断。

没有用游戏未提供的油压、水温、电压替代值。零油量、零增压等保持游戏原值，不假装采集到了其他传感器。实际游戏中的挡位编码、不同车型的数据表现仍需实测核对。

## 车型照片对照

「驾驶遥测」位于左侧「演示剧场」上方。15 张主题卡片上方是像素仪表，下方是对应车型的外观与内饰 / 仪表照片。点击仪表选用主题，点击照片查看大图和来源；照片为同款车型参考，并非保证同一辆实车，具体年份和版本在大图说明中标注。

照片随本地应用保存在 `telemetry-photos/`，查看时无需联网。卡片随窗口宽度自动调整列数，照片等比例放大后居中裁剪，铺满卡片的照片区域，不留黑边；点开大图仍能查看完整照片，并在需要绘制时才加载缩略图；不新增后台刷新任务。照片缺失时显示占位，不影响仪表主题和 USB 显示。

`telemetry-photos/manifest.json` 按主题 ID 对应外观、内饰文件及来源；新增或替换照片后重启应用。版权、作者及许可信息见同目录 `CREDITS.md`，照片不适用程序代码的许可证。

卡片中的年份来自主题的 `reference_year`，表示设计参考车型年份，不是当前游戏车辆的年份。像素屏不显示车型年份；留白处使用本机当前时间（HH:mm）或相应仪表。

## 添加和修改主题

仪表布局在程序旁的 `telemetry-themes/*.json` 中，运行时读取，不需要重新编译。修改后点击「重新加载仪表」；新增主题使用不同的 `id`。文件需要 `version: 1`、`id`、`name`、`description`、`color`、`commands`，可选 `sprites`。`color` 是发送给音响的 RGB，默认复用现有校准配色，仍可能有个体色差。

绘图沿用现有主题指令：`line`、`rect`、`erase`、`sprite`、`segments`、`raster` 等；新增 `micro`（3×5 标签）与 `seven`（数码管数字）。使用 `${speed}`、`${rpm}`、`${gear}`、`${boost}`、`${fuel}`、`${clock}`、`${max_rpm}` 等文字绑定；`max_rpm` 是游戏给出的发动机上限；`rpm_ratio`、`speed_ratio`、`throttle`、`brake`、`boost`、`fuel` 是 0–1 的表盘输入。`speed_ratio` 使用 300 km/h 量程，主车速数字仍显示实际值。`when` 为零时不绘制该指令。只支持受限算术表达式，不执行主题脚本。

## 数据与显示流程

游戏通过官方单向 UDP 接口发数据。软件解析 324 字节包，只保留最新一份；不会读取游戏进程内存，也不会向游戏发送控制命令。数据格式与设置依据 [Forza 官方 Data Out 文档](https://support.forza.net/hc/en-us/articles/51744149102611-Forza-Horizon-6-Data-Out-Documentation)。

接收器关闭时释放端口，开启后异步等待数据。仪表目标帧在节能模式最多每秒生成 5 次，均衡模式最多 8 次；真实屏幕速度取决于 USB 传输。传输泵合并待发送帧，只对已确认的上一帧做压缩／差分，不因每个车速变化取消正在发送的帧。仪表数值直接更新，不逐次触发整屏切换动画。沿用原来的独占、心跳和退出恢复机制，画面写入 RAM，不循环擦写 ROM。

Vector 左侧未选挡位为黑底亮字，当前挡位反色。R 表示倒挡，随后为 1–6；最后一格平时显示 7+，使用七挡及以上时显示实际挡位。右侧四列依次为油门、制动、增压（PSI 取整）和油量，数值在下方方格内。Alfa 的上斜条为转速，下斜条为油门，后者以亮底中的黑色进度表示占比。

## 验证范围

2026-10-29：600 项遥测与像素检查通过（包括连续弧形每个内部像素、挡位逐格反色、小时分钟切换），此前 192 项遥测测试通过，包括只改变最大转速时 15 套仪表均自动改变量程、非法上限不接管、无 DEMO / LIVE 屏幕标签。照片、年份和卡片通过四种窗口宽度的布局检查。

2026-10-28：通过固定字节偏移、截断包、非法数值、UDP 端口冲突、乱序包、断流、主题切换和演示结束恢复等自动测试；15 套主题已生成像素预览，检查了数字和刻度的排布。真实引擎测试使用本机模拟 UDP，硬件显示测试也使用模拟数据。

**2026-10-29，使用者已完成真实地平线 6 游戏测试，确认自动进入遥测、退出遥测和显示动画均正常。** 使用 HaloStudio 2.7.0 和 2025 款常规版 USB 一线通 Halo PixelBar；游戏具体构建号未记录。以上是使用者的实机反馈，不表示已逐项测量所有遥测字段或覆盖全部车型。USB 串行链路无法做到游戏级帧率；仪表设计侧重清晰读数与分段动态刻度。

开发者可运行以下离线验证，不连接音响：

```powershell
.\HaloStudioNet.exe --telemetry-test --output C:\Temp\halo-telemetry\unit.json
.\HaloStudioNet.exe --telemetry-integration-test --output C:\Temp\halo-telemetry\integration.json
.\HaloStudioNet.exe --preview --telemetry-demo --ui-page 5 --quit-after 20
```

`--telemetry-test` 会同时生成 `telemetry-atlas.png`。集成测试使用单独的 `integration-runtime`，不改动日常设置。
