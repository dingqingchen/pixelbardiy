# 调度与传输

主界面运行在 WinForms UI 线程。引擎在后台任务中读取不可变设置快照；异步媒体会话、歌词网络请求、传感器采样及 USB ACK 等待不会占住 UI 线程。每类采集至多保留一个在途任务。USB 分片发送与媒体轮询分离，快速切换主题时不会把歌词进度冻结在换色前。

USB 使用 SetupAPI 枚举、HidD 校验，以及独立输入、输出句柄上的无缓冲 overlapped FileStream。等待输入不会占用请求发送所需的流锁；发送与请求接收都有 1.5 秒超时。输入报告进入有界 Channel；请求通道只允许一个等待 ACK 的指令。每次写入由写信号量串行化。HID 序列化、RLE、XOR、CRC 为托管 C# 实现，离线测试包含已验证 Python 版的独立基准数据。

发送端只保留一个可替换目标、一帧正在传输的画面和一帧已经确认的基准。新歌词可在上一分片 ACK 后放弃未提交帧；下一 BEGIN 使用递增帧号重置 RAM 暂存。差分基准只随完整帧 CRC 确认推进，永远不跟随被放弃的画面。每 64 帧重新发送不依赖基准的关键帧。

屏幕控制指令白名单为 17 / 66 / 6A / 6B / EE / EF / C6。17 只接受带保留序号 `00 02 FF FF` 的 HPL2 数据；没有原资源上传 START/END，也没有固件更新或音量写入指令。显示租约有效时禁止 EF，更改颜色先 RELEASE，再原厂颜色/时钟与回读，再用新 SID ACQUIRE。

心跳不晚于空闲 500 ms，正常数据分片也刷新 MCU 租约。关机、正常退出和版本切换都会停止新画面，等待在途 ACK，释放显示权，再持续回读确认原厂时钟至少 2.5 秒稳定。释放响应不确定时先等待 2.2 秒租约过期。独占锁遵循旧版 Qt 锁文件的 PID/进程名/主机名格式，避免两个版本同时接管。

图形渲染器只读外部 JSON。单色画布为 1024 字节按页点阵；字体蒙版缓存上限 256。主题有独立指令预算、repeat 限制和表达式长度限制。不可执行代码，不可发 USB。预览直接读取发往设备的相同字节。

节能配置：无播放时媒体轮询 1.5 秒；监控 3 秒；没有可见监控页且默认不是监控时不采样；隐藏窗口不重绘，状态更新 3 秒；音乐峰值最多 20 Hz，均衡模式最多 30 Hz；驱动和模块只在必要时建立连接。日志上限 2 MB 加一个轮转文件。

温度 IPC 延续既有 `HALOTC02` 80 字节共享内存协议和请求事件。按需启动时先探测现有驱动；首次需要权限时用户点击「授权并重试」，保存授权模式后在后续启动恢复尝试，仍由 Windows UAC 决定是否允许。主程序不提升权限。序列号必须非零、偶数且前后一致，同时校验父/辅助 PID、CPU 家族、原始寄存器、驱动后端、样本数、时间戳与数值范围；10 秒以上旧数据不会显示。最多异步等待 100 ms，也接受上次请求延后完成的有效样本。退出状态保留实际错误原因；失败重试退避 60 秒，不循环弹 UAC。已有 WMI CPU 温度统一映射为 `cpu_temp`，避免主题找不到指标。

## 固件能力与动画调度

本机安装记录的已验证 SHA 决定能力：旧 RAM、codec、全屏动画、字符雨四级，不用共同的原厂 USB 版本号推断能力。旧 codec 的动画只移动 x=38..237、y=4..27；仅在歌词且区外像素不变时才可使用，否则合成整屏中间帧。全屏固件新增 ID 3/4（上推/揭幕），字符雨固件新增 ID 5。客户端只在确认支持时发送新 ID。

动画提交 ACK 后等待本地播放：中央 24 步、全屏 32 步、字符雨 160 步，按 metadata 间隔加 20 ms 余量。等待期间继续心跳，不把下一帧 BEGIN 提前塞进 MCU。紧急新画面可中断长字符雨；动画完成或中断后，MCU 与 PC 都以最后接受的完整目标作差分基准。

`demos/showcase.json` 是演示编排。字符雨段只产生一次目标提交，其后由 MCU 自行绘制；其余主题和歌词用有界目标队列。停止或结束演示不改用户设置。预览显示目标帧，不假装是硬件逐帧回传。

## 媒体与桌面开销

网易云实时歌词按 cloudmusic.dll 的 PE 时间戳和镜像大小选择经过验证的偏移，3.1.39 与 3.1.41 分开匹配；未知版本给出诊断，不盲用旧指针。进程仅申请查询/读取权限。每 3 秒更新 cloudmusic 窗口候选，缓存句柄后只读该窗口标题；GSMTC 元数据缓存 700 ms。空闲时仍每 600 ms 探测声音，避免“没有峰值所以永远不再采样”的闭环。

预览用缓存位图和一次 DrawImage 代替每次重绘的 8,192 次 GDI 调用，像素或颜色没变化就不重建。隐藏主窗口时跳过控件更新；监控表只在数值变化时更新。TempoHub 启动检查每 3 秒一次，检测到后释放本程序显示权。

## 2.4 界面分层与颜色

`StudioForm.cs` 管理窗口框架、导航、托盘、生命周期和状态绑定；`StudioPages.cs` 负责页面编排与设置行；`StudioControls.cs` 集中圆角按钮、开关、色板、主题卡与像素预览。参考 Clash Verge Rev 的统一页面框架与视觉分层，继续使用原生 WinForms。图标由自有 SVG 几何图案生成多尺寸 ICO，嵌入 EXE 并由窗口/托盘共享，不依赖默认系统图标。

`PagePanel.cs` 按当前 DPI 和有效宽度排列 1–3 列卡片，2.4.1 将下一张卡片排在当前最短列下方，避免整行被最高卡片撑开；实时硬件表等跨列卡片排在全部前序卡片下方。`SettingRow.cs` 在窄卡片内将宽输入控件排到标签下方，开关仍与标签并排。`ThemeGallery` 同样自适应 1–3 列，预览保持 8:1；`MonitorControls.cs` 统一传感器表与指标勾选。可变宽度的自绘控件使用双缓冲和 `ResizeRedraw`，避免只刷新新增区域而留下旧圆角残影。边框、背景、字体和间距共用 `Palette`。离线 `--preview --ui-audit <目录>` 执行同窗口反复缩放检查并保存布局证据。官方 Clash Verge Rev 布局参考及差异见 [UI_LAYOUT.md](UI_LAYOUT.md)。

`MonitorPairing.cs` 对已选指标按硬件家族稳定分组：CPU、内存、网络、磁盘和各个 GPU 先完成同类配对。2.4.1 将各组剩余项按固定类别位置（CPU → 内存 → GPU → 磁盘 → 网络 → 风扇 → 其他；GPU 风扇在 GPU 位置）继续就近配对，每次取距离最近的两个；等距优先靠前类别，再按传感器键排序。偶数项全部成对，奇数项仅最后一项单独显示，采样数值不影响配对。默认每次递进一个完整配对；`pair_advance=single` 仅在横向切换时逐个递进，向上切换仍按整对刷新。渲染身份包含两项指标键，确保配对变化能触发现有 MCU 切换动画。

`Settings.ThemeColors` 以主题 id 保存严格的 `#RRGGBB` 值，未覆盖时回落主题 JSON 原色。恢复原色只删除该主题覆盖值；主题文件不被改写。预览、日常帧、主题演示和律动主色使用同一颜色入口。换色遵循 RELEASE → 设置 RGB → 原厂时钟与颜色缓存稳定等待 → 新租约；等待中发生的选择合并到最新值。EE 是 USB 缓存回读，并非显示 MCU 执行回执，因此缓存正确不保证实机颜色准确。

2.4.1 的 `Settings.DeviceScreenColor` 仅将逻辑纯白映射为本机蓝通道校正值，连接、日常帧和主题演示走同一转换；预览与氛围灯继续使用原始颜色。传输控制器持有实际 RGB，原有回读与退出恢复流程无需修改。校正值默认 255，由本机 `screen_white_blue` 保存。

2.6.0 歌词先保留原始句与 YRC 单元，再按主题正文宽度生成有时间戳的页面。每页作为普通目标帧交给同一 USB 队列与 MCU 过场；无逐字数据仅规划首尾两页。详细时序、缓存与限制见 [歌词时间轴](LYRICS.md)。
